I Built Micropayments for the Agent Economy

Here's a problem nobody's solved yet: AI agents can't pay for anything.

Think about it. Millions of agents are out there right now — writing code, doing research, generating content. They call APIs, they consume compute, they use each other's services. But when it comes to actually exchanging value? Nothing. There's no wallet, no checkout button, no "pay 5 cents for this API call" that an agent can just use.

Stripe's minimum charge is around 30¢ plus 2.9%. That kills any transaction under a dollar. A 5¢ payment through Stripe would cost you 30¢ in fees alone. The maths doesn't work, so micropayments just… don't exist on the internet.

So I built NanoTab.

What NanoTab does

NanoTab lets anyone sell anything for fractions of a cent. It's built on USDC on Base (Coinbase's Layer 2), where transaction costs are a fraction of a penny. The fee is 0.1% — compared to Stripe's ~3%, that's roughly 30x cheaper.

The pitch is simple:

  • Sellers: one command to set up. npx nanotab-seller init and you're taking payments.
  • Buyers (including agents): one click — or one API call — to pay.
  • Amounts: $0.01, $0.05, $0.001 — whatever you want. The fee stays at 0.1%.

Why agents specifically?

Humans hate micropayments. Nobody wants to approve a 3¢ charge — the mental overhead isn't worth it. But agents don't have that problem. An agent can make a thousand 1¢ API calls without blinking, as long as the rails exist to settle them.

That's the bet: as agents become the primary consumers of digital services, they need payment infrastructure designed for machine-scale micro-transactions. Not adapted from human checkout flows — built from scratch for the agent economy.

Imagine an agent that pays 2¢ to query a specialist model, 0.5¢ to fetch real-time data, 5¢ to generate an image — all settled instantly, all on-chain, all auditable. That's the world NanoTab is building toward.

Live proof: it actually works

This isn't a whitepaper or a landing page with a waitlist. NanoTab is live on Base mainnet right now, and an agent has already paid $0.05 in USDC through the system — real money, real settlement, negligible fee.

Five cents. Settled on-chain. Fee of effectively zero. Try doing that with Stripe.

The stack

Everything is open source and on npm:

  • nanotab.dev — the site, docs, and live demo
  • github.com/HectorTries/nanotab — the full source code
  • nanotab-seller — one-command seller setup (npm)
  • nanotab-buyer — one-click buyer client (npm)

What I learned building this

The hardest part wasn't the smart contracts — Base makes that straightforward. It was the developer experience. Getting from "I want to accept micropayments" to actually accepting them needs to take under a minute, or nobody bothers. That one-command setup was the whole product decision.

The second hardest part was believing the fees could really be that low. When you're used to Stripe taking 30¢ off every transaction, a 0.1% fee on a 5¢ payment (that's $0.00005) feels like a rounding error. But on Base, it works — the chain fees are sub-cent, so there's almost nothing to pass through.

What's next

Right now NanoTab handles direct buyer-to-seller micropayments. The roadmap is streaming payments (pay per second of compute), agent-to-agent escrow, and usage-based API billing that charges per call instead of per month.

The agent economy needs money rails. I'm building them.

Try it, clone it, or tell me I'm wrong: head to nanotab.dev for the live demo, grab the code at github.com/HectorTries/nanotab, or just reply to this post — I'd love to hear what you'd charge fractions of a cent for.
